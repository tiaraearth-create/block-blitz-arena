# 🧱 Block Blitz Arena

ブロックブラスト風パズルゲーム — オンライン対戦・AI対戦・ランキング・ショップ・バトルパス・管理者パネルを備えたフルスタック実装です。

![Node](https://img.shields.io/badge/Node.js-%E2%89%A522-green) ![License](https://img.shields.io/badge/license-MIT-blue)

## ✨ 特徴

### ゲームプレイ
- **8×8グリッド** に3つのピースをドラッグ&ドロップで配置し、縦横のラインを消すクラシックなブロックパズル
- ⚡ **アルティメットスキル** — ラインを消すとゲージが溜まり、MAXでHUDの⚡ボタン（またはスペースキー）から**必殺技**が発動。11種類から1つを装備:

  | 奥義 | 効果 |
  |---|---|
  | 💥 破壊の衝撃波 | いちばん埋まった2行2列を強制消去（無料・初期装備） |
  | 🌊 浄化の波動 | お邪魔ブロック全消し＋下2行を消去 |
  | 🧲 重力圧縮 | 盤面を下端まで圧縮し、そろった行を消す（穴だらけの盤面を畳み直す） |
  | 🔥 オーバードライブ | 15秒間スコア**3倍** |
  | ☄️ メテオストライク | ランダムな14マスを大爆発で粉砕 |
  | 🌈 レインボーハンド | 手持ちが「連鎖するように選ばれた」最適3ピースに変化 |
  | 🛡️ 不落の城塞 | 30秒間コンボが途切れず、お邪魔ブロックも無効 |
  | ⏳ 時間停止 | 制限時間+12秒／ボス・サバイバルの攻撃を20秒封印／それ以外はリロール+3 |
  | ⚡ 神の裁き | 盤面を**完全消滅**させ超特大スコア |
  | 👁️ 断罪の一撃【王座限定】 | 縦横1列ずつを問答無用で消し飛ばす（王座の欠片で入手） |
  | 👑 全能【管理者】 | 盤面消滅＋ゲージ即再充填 |

  使用できるのはソロ・ボス・ボスラッシュ・ダンジョン・サバイバル・カオスのみ。**AI戦／オンライン／ウィークリーは公平性のため対象外**です。
- ゴーストプレビュー（消えるラインが光って予告）、コンボ&ストリークシステム
- **盤面ギミック** — ❄️**氷結**ブロック（2段耐久で、混じったラインはすぐには消えない）、✨**昇華**（盤面を完全に空にした瞬間の特別演出）、🧲**重力圧縮**（盤面を下端まで畳み直して穴を埋める）。モードによって登場
- パーティクル爆発・画面シェイク・コンボポップアップ・フローティングスコアなどのリッチな演出
- **WebAudioによる完全合成のBGM/効果音**（音声アセット不要）— 16ステップシーケンサー式の音楽エンジンが**モード別に18トラック**（メニュー/ソロ/バトル/おに/神など＋ブラスト系6曲）を演奏。ジュークボックスから試聴も可能

### メタゲーム
- 👤 **アカウント登録/ログイン**（pbkdf2ハッシュ + Bearerトークン、ゲストプレイも可）
- 📋 **ミッション** — プレイヤーごとに違う**デイリー3種／ウィークリー4種**を自動生成（デイリー25種・ウィークリー18種のプールから、ユーザーID+日付のシード式で抽選するので毎日入れ替わる）。全プレイの結果が自動で進捗に反映され、達成すればコイン/ジェム、全部集めればコンプリートボーナス。未受取があればメニューに🔴バッジ
- 🏅 **実績** — 6カテゴリ**122種**。進捗は保存された統計から毎回計算されるので、**過去のプレイにさかのぼって解除**されます。「まとめて受取」対応
- 📕 **コレクション図鑑** — スキン・ボード・エフェクト・アルティメット・ブースター・ガチャ限定・王座の欠片などを**セット単位**でコンプすると報酬（全10セット・満額で🪙90,500＋💎612）。報酬の受け取りは**1日1セットまで**（残りはまた翌日）
- 📊 **戦績ダッシュボード** — プロフィール→📊から、直近20戦のスコア推移グラフ（インラインSVG）と16項目のスタッツタイル（平均スコア・PvP勝率・⚡発動回数・連続ログイン etc.）
- 🏆 **グローバルランキング**（ハイスコア / PvPレートの2部門）
- 🏛️ **シーズン殿堂** — シーズンが切り替わると、直前シーズンのTOP3が**永久記録**として殿堂に刻まれる（上位3名にジェム・1位に刻印バッジ、住人も対象）
- 🏁 **ライバルボード** — 気になる相手を登録して、スコアやレートを直接見比べられる
- 🏷️ **日替わりショップ＋無料ギフト** — 毎日入れ替わるセール品と、ログインで受け取れる本日のギフト
- 📅 **デイリー／ウィークリーチャレンジ** — 全員同じシードの盤面で日替わり・週替わりに競う（リプレイ保存対応）
- 📦 **ゲスト引き継ぎ** — ゲストで遊んだ記録（統計・ブースター在庫など）をアカウント登録時に1回だけ引き継げる
- 🛍️ **ショップ** — コイン/ジェムで買えるのはブロックスキン9種・ボードテーマ8種・消去エフェクト6種・**アルティメット8種**・ブースター4種。これに加えて🎰**ガチャ限定3種**と👑**王座の欠片専用7種**が同じ棚に並ぶ（買えないぶんは入手先が表示される）
- 🎫 **バトルパス** — 30日シーズン制、30ティア、無料/プレミアムトラック、バッジ報酬
- 👑 **称号** — 条件を満たすと**61種**の称号を獲得、装備してランキングとプロフィールに表示（管理者はランキング対象外）
- 💎 **ジェム購入** — 4種のパック。既定（Stripe未設定）では購入は「💳 製作中」の案内を返し、`STRIPE_SECRET_KEY` を設定すると本物のStripe Checkoutに切り替わる。取引ログ・管理者売上表示付き
- 🎪 **期間限定イベント（8種）** — 🌪️カオスタイム／🪙コイン祭り（コイン2倍）／⭐経験値ブースト（XP2倍）／💎ジェムラッシュ（毎プレイ+3💎）／🐲ボス襲来（ボス報酬2倍・HP-20%）／⚡奥義祭（ゲージ2倍速）／🍀ラッキーデー（ガチャ20%オフ＋レア確率UP）／🔥倍々デー。管理者が種類・名前・期間を選んで開催、途中で延長・終了も可能
- 🗳️ **投票機能** — 管理者が投票を作成→全員にアナウンス→メニューのバナーから参加。**投票するまで結果は見えない**ので空気に流されない。**AI住人も性格に応じて投票**する（管理者画面で👤実人／🤖AIの内訳を確認可）。「次のイベント投票」なら1位のイベントをワンクリックで開催できる
- 💾 **バックアップ＆復元** — DLしたJSONをアップロード（または貼り付け）するだけで復旧。ログインできない初期化直後でも `/?restore=1` からバックアップ内の管理者パスワードで復元可能。既定は**マージ**（復元後に登録した人も残す・同名は進行度が多いほうを採用）。復元前は自動スナップショット、起動時にも自動保存されるのでワンクリックで巻き戻せる
- 🌐 **チャット自動翻訳** — 日本語⇄英語を自動翻訳して表示（原文はタップで切替、設定でOFF可）。外部APIキー不要の内蔵フレーズ辞書。`TRANSLATE_URL` を設定すれば LibreTranslate 互換の本格エンジンに切替
- 🏰 **ギルド** — 設立（🪙2,000）／公開・招待コード制／最大20人。メンバーの全試合が**週間ポイント**になり、ギルドランキングで競う。**週間クエスト**をみんなで達成すると**ギルド金庫**に報酬が貯まる。ギルドレベルに応じて**コインボーナス最大+20%**。チャット・ランキングに `[TAG]` 表示。AI住人のギルドもランキングに並ぶ
- 📰 **ニュース** — 運営のお知らせ一覧（固定・削除・全員アナウンス）。未読があればメニューに🔴
- 🎭 **にぎわいシステム 2.0（住人）** — AIプレイヤーは使い捨ての名前ではなく、性格を持った**64人の住人**（初心者／ガチ勢／エンジョイ勢／夜型／朝活勢／海外勢／ガチャ中毒／探索者／優しい先輩／小学生／配信者／ROM専）。各自に得意モード・活動時間帯・レート・口癖があり、**チャット・ランキング・対戦ボットに同じ名前と同じ強さで登場**。時間帯・曜日・開催中イベント・投票・入室した人に反応し、2〜4往復の会話もする。対戦した住人は後でチャットで「〇〇さん強すぎ…」と言ってくる。📡**ライブフィード**（メニューのティッカー）に住人の活動が流れ、本物のプレイヤーの快挙（新記録・バッジ・優勝・UR・実績）は⭐付きで流れる。人口は曜日・イベント・ランダムな「配信者バズ」で変動し、にぎわい度（🔥大盛況／にぎやか／🌙まったり）を表示
- 🎛️ **にぎわい設定 2.0（管理者）** — プリセット（標準／お祭り／🔥フィーバー／🌋伝説の夜／🌠祭りの極み／しずか／深夜／人口だけ／オフ）、**人口×0〜500**（住人の実数は×88で600人が上限、それより上は表示人数のみ増加）、チャット頻度、機能ごとのON/OFF（チャット・会話・フィード・挨拶・反応・ランキング住人・ボット）、静かな時間帯、住人の一覧（オンライン状態・性格・レート）と引退/復帰/追加/総入れ替え、カスタムセリフ（`{me}` `{mode}` `{event}` `{name}` 置換）、テスト送信
- 🛡️ **管理者パネル** — ユーザー管理（通貨付与・凍結・削除）、全体アナウンス、**シーズン管理（番号/名前/期間の変更・進行維持での巻き戻し対応）**、メンテナンスモード、ランキングリセット、DBバックアップDL、サーバー統計
- 🤖 **オートパイロット 3.0（管理者専用）** — ブレイン6種（見習い〜創造神）・速度x1〜x32・スタイル（通常／全消し狙い／コンボ重視／安全重視）・アイテム/奥義の自動使用・終了後の自動続行・目標スコア停止・稼働統計。HUDの🤖をタップで起動、長押しで設定
- 🛡️ **管理者コマンド 3.0** — 7タブ（盤面／スコア／手札／時間・敵／ダンジョン／奥義／ゴッド）＋コマンド入力（`/score 5000` `/floor 50` `/time +120` `/hp 1` `/mult 10` `/lives 9` `/ult judgement`）。ゴッドモード（無敵・お邪魔無効・コンボ永続・フィーバー永続・敵停止・スコア倍率×100）
- 👑 **管理者限定アイテム（∞・全モードで使用可）** — 💥神の一撃（盤面消滅＋50,000）／⌛時の支配（+120秒・敵60秒封印）／🎴創造の手札／🔱神威（30秒×10）／🛡️絶対防御（60秒無敵）／☄️天変地異（敵HP99%削り）。公平性のため、AI戦・オンライン・タイムアタックなどアイテムを無効化しているモードでは管理者でもアイテムバー・奥義は表示されない
- ⚖️ **敗北ルール** — オンライン対戦の切断/離脱は敗北（相手の不戦勝）。AI戦・ボス戦の途中終了は引き分け

### 環境変数
| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | 3000 | HTTPポート |
| `MATCH_SECONDS` | 120 | オンライン対戦の試合時間（秒） |
| `ROYALE_SECS` | 180 | バトルロイヤル1試合の長さ（秒・最低30） |
| `POP_SCALE` | 1 | にぎわい人口の基本倍率。住人のチャット・フィード・ランキング・ボットの量を調整（`0`で完全オフ）。管理者パネルの「🎭にぎわい設定 2.0」でゲーム内からも **×0〜×500**・プリセット・機能ON/OFFを調整可能（住人の実数は ×88 で600人の上限に達し、それより上は表示人数だけが増えます） |
| `ADMIN_PASSWORD` | （自動生成） | 設定すると管理者「るみまき」のパスワードを固定（8文字以上）。再デプロイしても変わらなくなる |
| `BACKUP_PASSPHRASE` | （未設定＝`ADMIN_PASSWORD`） | `server/seed-backup.json` の暗号鍵。32文字以上のランダム値を推奨。**取得側（`npm run backup:pull` / backupワークフロー）と本番の両方に同じ値**を入れること。片方だけだと復号できず、起動時の自動復元が黙って止まります |
| `SESSION_SECRET` | （起動ごとにランダム） | **ログイン状態をデプロイ/再起動後も維持**するための署名鍵（16文字以上の長いランダム文字列）。設定すると、データが消えている間もプレイヤーはログアウトされず、復元が終わった瞬間に自動でログイン状態に戻る。未設定だと再デプロイのたびに全員ログアウト |
| `TRANSLATE_URL` / `TRANSLATE_KEY` | なし | LibreTranslate互換APIのURL（と必要ならキー）。設定するとチャット翻訳が本格エンジンになる |
| `DATA_DIR` | `server/data` | データ保存先ディレクトリ（永続ディスクを別パスにマウントした場合やテスト用）。**Dockerイメージでは既定が `/data`**（Dockerfileが `ENV DATA_DIR=/data` を焼いている）ので、ボリュームは `/data` に当てること |
| `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | なし | 設定すると課金が「製作中」→本物のStripe決済に切り替わる |
| `TRUST_PROXY` | `1` | Express の `trust proxy` 設定。**HTTP のレート制限だけでなく、WebSocket の同時接続上限とゲストのチャット連投制限も、この設定で解いた接続元IPで数える**（`server/index.js` の `clientIpOf`）。数値＝信頼するホップ数。**LB/リバースプロキシ無しで直結公開するなら必ず `0`**（`false`/`off` も可）── 既定の `1` のままだと、クライアントが自分で付けた `X-Forwarded-For` がそのまま接続元IPとして採用され、IPごとの上限を振り分けて回避されうる。サブネット指定（`loopback` や `10.0.0.0/8` 等）も書けるが、その場合 WS 側は安全側に倒して XFF を見ない（HTTP と挙動が変わるので、プロキシ背後ではホップ数の数値指定を推奨）。前段が2段（CDN＋LB 等）なら `2` を指定しないと全員が同じ中間IPに畳まれ、新規プレイヤーが接続上限で弾かれる。管理画面 `/api/admin/stats` の `conn.distinctIps` が人数のわりに極端に小さいときは、この設定を疑うこと |
| `SEED_RESTORE` | `1` | 起動時の `seed-backup.json` からの自動マージ復元。永続ディスク運用が安定したら `0` で止められる |
| `ASSET_HASH` | `1` | 配信JS/CSSの内容ハッシュによる長期キャッシュ。変換で不具合が出たときは `0` で丸ごと無効化できる逃げ道 |
| `RENDER_EXTERNAL_URL` / `KEEPALIVE_URL` | なし | 設定すると10分ごとに自分の `/api/status` を ping してスリープを防止（無料枠のスピンダウン対策）。`RENDER_EXTERNAL_URL` は Render が自動で入れる |
| 試合時間の調整用 | （各既定値） | `TOURNEY_SECS`（トーナメント各ラウンド秒・例 `60,60,90`）／`COOP_TURN_MS`・`COOP_MAX_SECS`（協力プレイの手番/上限）／`LAND_TURN_MS`（採掘場の手番）／`ZERO_DEAL_AT`／`SEED_BACKUP_FILE`。通常は変更不要 |

## 🌍 公開する（デプロイ）

### 1. GitHubへプッシュ
```bash
git remote add origin https://github.com/<あなたのユーザー名>/block-blitz-arena.git
git push -u origin master
```

### 2. ホスティング
**Render** (おすすめ・簡単):
1. [render.com](https://render.com) で「New → Web Service」→ GitHubリポジトリを接続
2. Build Command: `npm ci --omit=dev` / Start Command: `npm start`
   （`npm install` だと lock を無視して CI が一度も試していない依存の組み合わせで起動しうる。
   `render.yaml` でデプロイすればこの設定と `NODE_VERSION=22` が自動で入ります）
3. **「Disks」で永続ディスクを追加**し、Mount Path を `/opt/render/project/src/server/data` に
   （無料プランでは選べません。これが無いと再起動のたびにセーブデータが消えます）
4. デプロイが終わったら、GitHub の Settings → Secrets and variables → Actions に
   **2つとも**登録する（片方だけだと、そちらのワークフローが毎回赤くなります）:
   - **`PROD_URL`** … 本番URL（例 `https://<あなたのサービス名>.onrender.com`）。
     30分おきの外形監視（`.github/workflows/watchdog.yml`）と毎日のバックアップが使う
   - **`ADMIN_PASSWORD`** … Render の Environment に入れたものと**同じ文字列**。
     毎日のバックアップ（`.github/workflows/backup.yml`）がこれでログインし、
     取れたデータをこのパスワードで暗号化する

**Railway / Fly.io** も同様（`PORT` は自動注入、対応済み）。**Docker** も可:
```bash
docker build -t block-blitz .
docker run -p 3000:3000 -v bba-data:/data -e DATA_DIR=/data \
           -e SESSION_SECRET=<16文字以上のランダム文字列> \
           -e ADMIN_PASSWORD=<管理者パスワード> block-blitz
```

> **⚠ ボリュームは必ず `/data` に当てること。** イメージには `ENV DATA_DIR=/data` が
> 焼かれている（Dockerfile）ので、db.json が書かれるのは常に `/data` です。
> ここを `/app/server/data` にすると、当てたボリュームは一度も書かれない空のまま残り、
> 実データは `VOLUME ["/data"]` が作る**匿名ボリューム**に入ります。コンテナを作り直すと
> 新しい匿名ボリュームが割り当てられるので、前のアカウント・スコア・ジェムには
> 二度と辿り着けません（`db.meta.seedHash` も消えるため、初回起動あつかいで
> 同梱 seed が再適用されます）。`session-secret.txt` と `snapshots/` も同じ
> `DATA_DIR` 配下なので巻き添えになります。

### 3. 公開後の注意（⚠️まず読んでください）

#### ✅ 永続ディスクがある場合（Starterプラン・推奨）
`render.yaml` が `plan: starter` ＋ `disk` になっていれば、`server/data` は
ディスクに保存されるので**デプロイでも再起動でもデータは消えません**。
push するだけで更新が完了します。事前の `npm run backup:pull` は不要です。

> **ディスクを後から付けるときは順番に注意。** 新しいディスクは空の状態で
> 作られるため、その初回起動で `server/seed-backup.json` が1回だけ適用され、
> それがディスクの初期状態になります。移行の直前に `npm run backup:pull` を
> 実行して seed を最新化してから push してください。
> （`db.meta.seedHash` により、同じ seed が二度適用されることはありません）

ディスク運用が安定したら、環境変数 `SEED_RESTORE=0` で自動復元を止めても
かまいません（`seed-backup.json` は最後の保険として残しておけます）。

#### ⚠️ 無料プランの場合の更新手順（自動復元）
無料プランには永続ディスクがありません。**デプロイ時だけでなく、15分アイドルで
スピンダウンして再起動するたびに `server/data` が消えます。** そのため
アップデートを push する**前に**、毎回このコマンドが必要です：
```bash
npm run backup:pull
```

本番サーバーから最新バックアップを取得し、**管理者パスワードで暗号化**して `server/seed-backup.json` に保存します（公開リポジトリでも安全）。これをコミットして push すると、**デプロイ後のサーバーが起動時に自動でマージ復元**します — `/?restore=1` を開く必要はもうありません。

- 必要条件: Render の Environment に `ADMIN_PASSWORD`（取得時に入力したものと同じ）と `SESSION_SECRET` を設定しておくこと
- シーズン・バトルパスは v2.6 から**固定の暦から計算**されるので、そもそもデプロイでリセットされません（実績の受取状況・イベント・投票・にぎわい設定もバックアップから自動で戻ります）
- 自動復元を止めたいとき: 環境変数 `SEED_RESTORE=0`
- メンテナンスモードの ON/OFF 状態はバックアップには含まれません（復元しても引き継がれないので、復元後の機体で必要なら管理者パネルから入れ直してください）

#### 従来の手動復元（バックアップを取り忘れたときの保険）
> `git push` 前に管理者パネル →「💾 バックアップDL」でJSONを保存。
> デプロイ完了後は **`https://<あなたのURL>/?restore=1`** を開く → ファイルを選ぶ → **バックアップ時点の管理者パスワード**を入力 → 「♻️ 復元する」を2回押す。
> 既定のマージ復元なら、その間に新規登録した人も消えません。`SESSION_SECRET` を設定しておけば**プレイヤーはログアウトされず**、復元完了と同時に自動でログイン状態に戻ります。恒久対策は `render.yaml` の永続ディスク（Starterプラン）です。

- 初回起動ログ（またはディスク内の `server/data/admin-credentials.txt`）から**管理者パスワードを控えて保管**
- HTTPSはホスティング側が終端します（クライアントは自動で `wss://` を使用）
- 認証エンドポイントにはレート制限（20回/5分/IP）を内蔵
- 更新をデプロイする前に管理者パネルの「🛠 メンテナンス」→「💾 バックアップDL」の利用を推奨

## 🗓 運営（日次・週次）— 引き継ぐ人はここを読む

### 自動で回っているもの（GitHub Actions）
| ワークフロー | いつ | 何をする | 必要な Secret |
|---|---|---|---|
| `.github/workflows/watchdog.yml` | 30分おき | `/api/status` を叩き、応答が無いか `persistError` が出ていたら失敗させる（GitHubがメールで知らせる） | `PROD_URL` |
| `.github/workflows/backup.yml` | 毎日 18:10 UTC（JST 翌03:10） | 本番のデータを取得し、暗号化して `server/seed-backup.json` にコミットする。**事実上これが唯一の自動バックアップ** | `ADMIN_PASSWORD` / `PROD_URL`（任意で `BACKUP_PASSPHRASE`） |
| `.github/workflows/ci.yml` | push / PR のたび | `npm test`（29本）と `npm audit --audit-level=high` | なし |

> Secret が足りないと、そのワークフローは**毎回赤くなり続けます**。Actions タブが
> 赤いまま放置されると、本番が本当に死んだ日に誰も気づけません。まず赤を消すこと。

### 毎日
1. 管理者パネル → **🐛 バグ報告** … 未処理のものを確認し、直したら ✅ で処理済みに
2. 管理者パネル → **⚠️ クライアントエラー** … 未解決の件数が急に増えていたら、その日の更新を疑う
3. Actions タブの **backup** が緑か（赤なら本番かパスワードの問題。放置するとバックアップが止まる）

### 毎週
1. 管理者パネル → **👑 管理者イベント** … 開催曜日と時間枠（JST・最大6個）を設定
   - ⚠️ **枠を減らす／時刻を変えると、そこを予約済みの人の予約がずれます。** 週の途中では触らないこと
   - 新しいモードを試すときは「試運転 ON」にすると、一般プレイヤーには見えないまま自分だけ確認できます
2. `server/seed-backup.json` の更新コミットが1週間ぶん積まれているか（積まれていない＝バックアップが止まっている）

### 🔑 管理者パスワードを変えるとき（手順を守らないと復旧できなくなります）
`server/seed-backup.json` は **`BACKUP_PASSPHRASE`（未設定なら `ADMIN_PASSWORD`）で
AES-256-GCM 暗号化**されています。つまりこの値は「バックアップの復号鍵そのもの」で、
変えると**リポジトリにコミット済みの過去の seed が全部開けなくなります**。
しかも復号に失敗しても、出るのは起動ログの `[seed] …復号に失敗しました` という
1行だけで、`/api/status` にも管理者パネルにも出ません（**災害復旧の当日に初めて分かる**）。

正しい順番:
1. ホスティング（Render）の Environment の `ADMIN_PASSWORD` を変えて再デプロイ
2. GitHub の Secret `ADMIN_PASSWORD` を**同じ値**に更新する（忘れると翌日からバックアップが止まる）
3. すぐに `npm run backup:pull` を1回実行し、新しいパスワードで seed を焼き直してコミットする

- **管理者パスワードは、管理者パネルの 🔑 ではなく `ADMIN_PASSWORD` 環境変数で変えてください。**
  🔑 で変えても、次の再起動で `pinAdminPassword()` が環境変数の値に**書き戻し、
  発行済みトークンを全部失効させます**（画面はこれを警告しません）。
- バックアップの鍵を管理者パスワードから切り離したいときは `BACKUP_PASSPHRASE`
  （32文字以上のランダム値）を、**本番の環境変数と GitHub Secret の両方に同じ値で**設定します。
  片方だけだと復号できず、自動復元が黙って止まります。

### バックアップが「削られた」とき
`db.json` が復元上限（4MB）を越えると、サーバーは収まるまで
`dailyReplays` → `clientErrors` → `txArchive` → `workshop.likedBy` の順に中身を削ってから返します。
`npm run backup:pull` と backup ワークフローは、削られた場合に警告（Actions では注釈）を出します。
出ていたら db を減らしてください。放置すると、**工房の「いいね済み」名簿を欠いたバックアップ**が
毎晩積まれ続けます（復元後に♡を二重に押せるようになります）。

## 💳 本物の課金を有効にする（Stripe）

コードは実装済みです。Stripeのキーを設定した瞬間にデモ決済が本物のStripe Checkoutに切り替わります：

1. [stripe.com](https://stripe.com/jp) でアカウント作成（本番利用には事業者情報の登録が必要）
2. ダッシュボード →「開発者」→「APIキー」から **シークレットキー**（`sk_...`）を取得
3. 「開発者」→「Webhook」→「エンドポイントを追加」で URL に `https://<あなたのドメイン>/api/stripe/webhook`、イベントは `checkout.session.completed` を選択 → **署名シークレット**（`whsec_...`）を取得
4. Render の Environment に設定：
   - `STRIPE_SECRET_KEY` = `sk_...`
   - `STRIPE_WEBHOOK_SECRET` = `whsec_...`

仕組み: カード情報は**Stripeのホスト決済ページ**でのみ入力され、このサーバーは一切触れません。ジェム付与は**署名検証済みWebhook**経由のみ（クライアント申告では付与されません）。テストは `sk_test_...` キー＋カード番号 `4242 4242 4242 4242` で安全に行えます。

⚠️ 実際に販売する場合は特定商取引法に基づく表記・利用規約の整備を忘れずに。

## 🔒 セキュリティ / 公平性
- パスワードは pbkdf2(12万回) + ソルトでハッシュ化
- セッションは HMAC-SHA256 署名付きトークン（`SESSION_SECRET`）。DBに依存しないのでデータ初期化後も有効、ログアウト/パスワード変更は失効リストと発行時刻で無効化
- スコア送信はサーバー側でレート上限チェック（チート対策）
- 対戦は同一シードのピース列を両者に配布して公平化
- 管理者APIはロールベースで保護
